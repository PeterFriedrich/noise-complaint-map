### ❌ Blocking Issues

Nothing blocking.

Two **correctness gaps found while porting, filed in `TODO.md` and deliberately
NOT fixed** (a docs port was the wrong PR for them; both touch pipeline code and
want their own tests):

1. **`pipeline/fetch.py` has no download-completeness guard.** `fetch_all()`
   pages with `$limit=1000`/`$offset` and stops when a batch comes back short —
   it never compares its total against what the server says it holds. Socrata
   truncates *silently*: a partial response is a valid response. A short fetch
   would publish a thinner map with every test still green. Fix: query
   `$select=count(*)` with the same `$where`, compare, fail hard on mismatch.
2. **`site/data/meta.json` records a build timestamp, not a data timestamp.**
   If Socrata stalls, the site keeps saying "last updated today" because the
   *build* ran. Fix: record the publisher's own last-updated stamp, surface the
   older of the two, and have any guard measure the data (max `date_created`),
   never a metadata string.

## 4. Technical Learnings

**This container (web session) — full detail in `docs/REMOTE_VM.md`, written this session:**
- No conda, no `.env`, **pytest not installed** → `pip install -r requirements-ci.txt`.
- No `gh` CLI → GitHub work goes through the `mcp__github__*` tools.
- `data.edmonton.ca` is behind the proxy allowlist, so `pipeline/fetch.py`
  **cannot run here**. The fix is the owner's, in the environment's network
  settings, and applies to new sessions only.
- Consequence: `.githooks/pre-push` shells out to `gh`, so in a web container it
  fails open on its first line — **it is a no-op here, not protection.** The
  real backstop is the `merge-base --is-ancestor` check in §2.

**Porting adaptations — do not re-derive:**
- Template assumes `src/`, `master`, `.venv`; this repo is `pipeline/`, `main`,
  conda. All adapted in the copied files.
- `handoff_gap.py`'s `SUBSTANTIVE` paths exclude `site/data/` on purpose — the
  nightly pipeline rewrites it, so counting it would fire the nag every day over
  work no human did.
- `check_doc_citations.py` excludes `site/` as generated output, and its
  `EXCLUDE_NAMES` had `CODEMAP.md` removed (no such file here).
- **CI must use `python -m pytest`, not bare `pytest`** — the tests do
  `from pipeline.transform import …`, which only resolves because `-m` puts the
  repo root on `sys.path`. A bare `pytest` invocation in CI would fail on import.
- `check_decisions_log.py` has `CUTOFF = date(2026, 9, 17)`. Rows dated before it
  are grandfathered, which is why the 6 seeded historical decisions carry
  `2026-06-20` and pass without citing tests.

**GitHub API gotcha:** `pull_request_read method=get_status` returned
`total_count: 0, state: pending` for a commit whose Actions run had already
succeeded. That endpoint is the legacy *commit-status* API and does not see
Actions *check runs*. Read the workflow run (`actions_list`) for the real
signal. If branch protection is ever configured, require the check by name
rather than trusting a status rollup.

**The mid-session-merge footgun is real, not theoretical.** PR #1 was opened
21:11Z and merged ~22:58Z while this session was still live; PR #2 was opened
23:08Z and merged 23:09Z — **within a minute**. Both times the branch had to be
restarted from `origin/main` rather than stacked on. This is exactly what
`.githooks/pre-push` exists to catch, and exactly why §2 verifies with
`merge-base` instead of trusting a green merge notification.

**`session-summary/` is now at the limit.** Three files live at top level
(`2026-06-20.md`, `2026-09-21.md`, this one) and `tests/test_loaded_path.py`
enforces `MAX_LIVE = 3`. **The next handoff must first archive the oldest:**
`git mv session-summary/2026-06-20.md session-summary/archive/` — in the same PR,
or the merge gate fails. Archiving is not deletion; the archive is append-only
and a separate test refuses any deletion from it.
